# Planning

## Description

Turn a goal into a concrete, traceable plan — a project, a set of tasks, or
a roadmap update — rather than proceeding on an implicit or unwritten plan.

## Scope

Applies when starting new work of any real size: a new project, a
significant feature, a research effort. Not needed for genuinely small,
single-step tasks.

## Inputs

A goal or problem statement, and its connection (if any) to
`strategy/vision.md` or `strategy/roadmap.md`.

## Required Context

`strategy/roadmap.md`, `templates/project-template.md`,
`templates/task-template.md`.

## Process

1. State the goal and check whether it traces to an existing
   `strategy/roadmap.md` priority; if not, decide consciously whether to add
   one or proceed as unattached exploratory work.
2. Decide the right container: `projects/` (multi-step, ongoing) or `tasks/`
   (single, ephemeral action) — see `tasks/README.md` for the distinction.
3. Draft the plan using the matching template.
4. Identify which `skills/` and `workflows/` the plan will invoke.
5. Record the plan before starting execution.

## Outputs

A new or updated `projects/` entry, and/or one or more `tasks/` entries.

## Validation Criteria

The plan is written down (not just held in conversation), traces to
strategy or explicitly doesn't, and names the skills/workflows it depends on.

## Improvement Rules

If plans routinely need restructuring mid-execution, that's a signal the
planning step was rushed — increase the amount of upfront checking against
`strategy/` and existing `domains/`/`knowledge/` content next time.
